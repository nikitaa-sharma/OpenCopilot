  SECTION 1: FEATURE UPDATES — SARVAM AI RAG CHAT INTEGRATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1.1  WHAT CHANGED
    The existing "Ask About This Repository" RAG chat was powered by Ollama
    (llama3.2:3b) as the sole LLM provider. This update replaced the chat
    LLM with Sarvam AI (sarvam-105b) while keeping pgvector retrieval intact.

1.2  NEW FILES CREATED
    • backend/app/services/sarvam_provider.py
        — SarvamProvider class implementing the LLMProvider abstract interface.
        — Talks to the Sarvam AI chat-completions API (https://api.sarvam.ai/v1).
        — Supports conversation history, JSON mode, and configurable temperature.

    • backend/app/services/llm_factory.py
        — Centralized factory function: get_llm_provider(provider_name).
        — Resolves "sarvam", "ollama", "openai", or "groq" into concrete
          LLMProvider instances based on environment configuration.

1.3  FILES MODIFIED
    • backend/app/core/config.py
        — Added granular provider routing settings:
            CHAT_LLM_PROVIDER = "sarvam"
            ANALYSIS_LLM_PROVIDER = "ollama"
            STRUCTURE_EXPLAINER_LLM_PROVIDER = "ollama"
        — Added Sarvam-specific config fields:
            SARVAM_API_KEY, SARVAM_BASE_URL, SARVAM_CHAT_MODEL

    • backend/app/chat/service.py
        — RepositoryChatService now resolves its LLM provider via
          settings.CHAT_LLM_PROVIDER (defaults to "sarvam").
        — All existing RAG retrieval, source validation, and JSON parsing
          logic is preserved unchanged.

    • backend/app/services/repository_analysis_service.py
        — Explicitly routes through ANALYSIS_LLM_PROVIDER = "ollama".

    • backend/app/services/structure_explainer_service.py
        — Explicitly routes through STRUCTURE_EXPLAINER_LLM_PROVIDER = "ollama".

    • backend/app/services/llm_provider.py
        — Added .name attribute to OllamaProvider and OpenAICompatibleProvider.
        — Re-exported SarvamProvider for convenient import.

    • backend/.env / backend/.env.example
        — Added all Sarvam environment variables (API key, model, base URL).
        — Documented per-feature provider routing variables.

1.5  RAG PIPELINE (UNCHANGED)
    The retrieval pipeline is fully preserved:
      → User question
      → Sentence Transformers (BAAI/bge-small-en-v1.5) generates query embedding
      → pgvector cosine similarity search (384-dim vectors)
      → Keyword fallback if no vector results
      → Bounded context window assembled
      → Sarvam AI generates grounded answer with verified file citations
      → Source validation strips hallucinated paths

  SECTION 2: FEATURE UPDATES — FLOATING LIVEKIT VOICE AGENT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

2.1  WHAT WAS ADDED
    A fully functional floating voice assistant that enables developers to
    ask questions about a repository using their voice. The assistant uses
    Sarvam AI for speech-to-text, chat reasoning, and text-to-speech,
    orchestrated by LiveKit Agents with Silero VAD for voice activity detection.

2.2  BACKEND FILES CREATED
    • backend/app/voice/__init__.py
        — Package initializer for the voice module.

    • backend/app/voice/agent.py
        — Main voice agent entrypoint (voice_agent_entrypoint).
        — Integrates: Silero VAD → Sarvam STT → Sarvam LLM → Sarvam TTS.
        — Implements search_repository function tool for RAG retrieval.
        — Publishes real-time transcripts over LiveKit data channel.
        — Extracts repository metadata from room/participant metadata.
        — Includes error handlers, reconnection events, and VAD pre-warming.

    • backend/app/voice/worker.py
        — CLI entrypoint: python -m app.voice.worker dev
        — Validates LiveKit credentials before starting.
        — Registers prewarm_vad in WorkerOptions for fast cold-start.

    • backend/app/api/v1/endpoints/voice.py
        — POST /api/v1/voice/token endpoint.
        — Generates LiveKit participant tokens with repository metadata.
        — Returns server URL and token for frontend WebRTC connection.
        — Returns 503 if LiveKit/Sarvam credentials are missing.

2.3  FRONTEND FILES CREATED
    • frontend/context/voice-assistant-context.tsx
        — VoiceAssistantProvider React context with full session lifecycle.
        — Manages: microphone access, LiveKit Room connection, audio playback,
          mute/unmute, transcript collection, audio level visualization.
        — Handles events: TrackSubscribed, ActiveSpeakersChanged,
          DataReceived, Reconnecting, Reconnected, Disconnected.
        — Robust error handling for: permission denied, unsupported browser,
          unconfigured backend, and connection failures.

    • frontend/components/voice/floating-voice-assistant.tsx
        — Floating circular button with animated audio visualizer ring.
        — Expandable chat panel with scrolling transcript display.
        — Status indicators: disconnected, connecting, listening, speaking.
        — Mute/unmute toggle and session start/end controls.
        — Matches existing dark-themed design language.

2.6  VOICE PIPELINE ARCHITECTURE

    User speaks into microphone
      → WebRTC audio stream to LiveKit Cloud (India South region)
      → Silero VAD detects speech boundaries
      → Sarvam STT (saaras:v2.5) transcribes speech to text
      → Sarvam LLM (sarvam-105b) generates response
        ↳ search_repository tool: queries pgvector/keyword RAG
      → Sarvam TTS (bulbul:v3, speaker: kavya, 24kHz) synthesizes speech
      → WebRTC audio stream back to browser
      → Real-time transcript published over LiveKit data channel

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

3.1  SARVAM TTS MODEL DEPRECATION FIX
    • Problem: Sarvam AI deprecated model "bulbul:v2" (with speaker "anushka"),
      causing HTTP 400 errors and LiveKit ChanClosed channel exceptions.
    • Fix: Upgraded to "bulbul:v3" with compatible speaker "kavya" and
      standard sample rate 24000 Hz.

3.2  WINDOWS LIVEKIT NATIVE RESAMPLER CRASH MITIGATION
    • Problem: Microsoft Visual C++ runtime assertion failure in
      livekit_ffi.dll (soxr-sys/fft4g_cache.h, line 13: LSX_FFT_BR == NULL).
    • Fix: Running voice worker in "dev" mode avoids multi-process IPC
      supervisor ping timeouts and socket reuse collisions on Windows.
      Added VAD pre-warming (prewarm_fnc) to prevent audio stream init delays.

3.3  RESILIENT SESSION ERROR HANDLING
    • Added comprehensive error event handlers on the voice session.
    • TTS-related errors do not trigger cascading audio synthesis failures.
    • Auto-reconnection events (Reconnecting, Reconnected) propagated to
      the frontend status indicators.
    • Room disconnection triggers clean session teardown.

3.4  TEST COVERAGE
    • Added backend/tests/test_voice_agent.py with regression tests for:
        — TTS model and speaker compatibility validation.
        — VAD pre-warming function behavior.
        — Sample rate configuration validation.
    • Full test suite: 387 tests passed successfully.
